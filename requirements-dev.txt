# Repo-root development / test dependencies. NOT deployed.
#
# Runtime requirements live in `requirements.txt` (AgentCore supervisor) and
# `requirements-tier2-lambda.txt` (Tier 2 Lambda bundle). Nothing here ships:
# adding a linter to either would grow a Lambda artifact for no runtime benefit.
#
# Created 2026-09-20 by spec 2026-09-18-avx-tier2-ios-cards-and-actions Group 5.
# Review Cycle 4 asked for a lint gate to close the class behind its Critical (an
# `F821` undefined name in an exception handler, which made the handler raise on
# every invocation while reading as protection). Cycle 5 noted the gate's
# dependency was undeclared, so the gate was red on any machine but the author's.
#
# ---------------------------------------------------------------------------
# Running the executor test suite from a clean venv
#
#   pip install -r requirements-dev.txt
#   python -m pytest agents/executors/ -q                    # 352 passed
#   python -m pyflakes agents/executors/*.py                 # silent = clean
#   python agents/executors/tests/mutation_battery.py         # CAUGHT 39/39
#
# THIS FILE IS NOW SELF-SUFFICIENT for that suite. It previously was not: the
# dependencies were split across this file and `agents/supervisor/requirements-dev.txt`
# and NEITHER ONE ALONE was enough, while `boto3`, `requests` and `responses` were
# declared nowhere at the repo root at all:
#
#   boto3       imported at module scope by ios_owner.py:40
#   requests    imported at module scope by dms.py:47, vehicle_command.py:37
#   responses   imported by tests/test_{dms,registry,vehicle_command}.py
#
# All three are declared below. `boto3` and `requests` are also declared in
# `agents/supervisor/requirements.txt`, but that is a RUNTIME file for a different
# deployable — installing it to run tests pulls the whole AgentCore stack.
#
# Versions are EXACT, per `~/.kiro/steering/dependency-versions.md` ("All
# dependency versions MUST be pinned to exact versions"), and each is the version
# the 352-test suite and the 39-entry mutation battery are green against on
# 2026-09-20, read from `pip freeze` rather than chosen. An earlier revision of
# this file argued for leaving them unpinned so as not to constrain other
# packages' tests; that reasoning is superseded — steering requires pins, and an
# unpinned shared dev dependency is how a suite silently starts testing a
# different library than the one it was reviewed against.
#
# Residual, deliberately not changed here: `agents/supervisor/requirements-dev.txt`
# still carries `pytest>=8.0.0` and `pytest-asyncio>=0.23.0` as ranges. `pytest`
# is pinned below so this suite is deterministic regardless, but `pytest-asyncio`
# is not installed in this venv, so pinning it would mean inventing a version
# rather than recording a verified one. That file belongs to the supervisor's own
# test setup; pinning it wants that suite in scope.
# ---------------------------------------------------------------------------

# file — so on any machine but the author's it SKIPPED, and a skipped guard and a
# passing guard look identical in a summary line. That is the same lesson this file's
